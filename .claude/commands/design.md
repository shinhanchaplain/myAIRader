사용자 입력: $ARGUMENTS

위 입력에 해당하는 기능의 **화면 디자인만** 설계하고 개발한다. 비즈니스 로직, 데이터, API, 기능 동작은 만들거나 바꾸지 않는다.

모든 응답과 문서는 한국어로 작성한다. 코드 식별자는 원문을 유지한다.

## 0. 입력 확인

- 입력이 비어 있으면 작업을 시작하지 말고 "어떤 화면을 디자인할지 알려 주세요. 예: /design 할 일 목록 화면, 완료 항목은 취소선과 흐린 색으로 표시"라고 안내하고 멈춘다.
- 입력에 대상 프로젝트나 파일 경로가 없으면 `myAgent/` 아래를 `Glob`으로 확인한다. 프로젝트가 하나면 그 프로젝트를 쓰고, 여러 개면 어느 프로젝트인지 묻고 멈춘다.

## 1. 현황 파악

- 대상 프로젝트의 UI 파일(스타일, 템플릿, 컴포넌트)을 찾는다.
- `myAgent/docs/<프로젝트명>/design.md`가 있으면 기존 디자인 방향(색, 글꼴, 톤)을 읽고 따른다.
- 기능 설명에 해당하는 기존 화면이 있으면 현재 상태를 `Read`로 확인한다.
- UI 코드가 아직 없으면 디자인 문서만 만들고, 코드는 프로젝트 구조가 정해진 뒤 적용한다고 명시한다. 새 프로젝트 폴더는 만들지 않는다.

## 2. 디자인 설계

다음 내용을 `myAgent/docs/<프로젝트명>/ui-design.md`에 작성한다. 같은 이름의 파일이 있으면 `Read` 후 갱신한다.

- **화면 목적과 사용자 행동**: 사용자가 이 화면에서 무엇을 하는지 한 문장으로 적는다.
- **레이아웃**: 영역 배치를 ASCII 와이어프레임으로 그린다. 모바일과 데스크톱 차이가 있으면 둘 다 그린다.
- **디자인 토큰**: 색상(기본, 강조, 배경, 텍스트, 오류, 성공), 간격 단위, 글꼴 크기 단계, 모서리 반경, 그림자. 기존 토큰이 있으면 재사용하고, 새로 정의한 값만 표시한다.
- **컴포넌트 목록**: 버튼, 입력창, 목록 항목, 카드 등 각각의 기본·hover·focus·disabled·오류 상태를 표로 정리한다.
- **상태별 화면**: 빈 상태, 로딩, 오류, 데이터 많음, 데이터 없음.
- **접근성**: 명도 대비(WCAG AA 4.5:1 이상), 포커스 표시, 색에만 의존하지 않는 정보 전달, 키보드 조작 순서.
- **반응형 규칙**: 브레이크포인트별 변화.

## 3. 디자인 개발

UI 코드가 있으면 다음을 적용한다.

- 스타일 파일, 클래스, 테마 변수, 컴포넌트의 표현 부분만 수정한다.
- 토큰은 변수로 정의하고 값은 한 곳에서만 관리한다.
- 마크업은 클래스나 구조 같은 표현 요소만 바꾼다. 이벤트 핸들러, `id`, `name`, 폼 필드 이름, 함수 시그니처는 그대로 둔다.
- 콘솔 프로그램이면 출력 서식(줄맞춤, 구분선, 제목, 한글 표시 폭)만 다룬다. 메뉴 번호와 입력 순서는 바꾸지 않는다.
- 외부 라이브러리, 폰트, 이미지를 임의로 추가하지 않는다. 필요하면 설계 문서에 제안으로만 적는다.

## 4. 검증

- 프로그램을 실행해 화면이 깨지지 않는지 확인한다. 웹이면 주요 화면을 확인하고, 콘솔이면 출력을 본다.
- 기존 테스트가 있으면 실행한다. 실패하면 디자인 변경 때문인지 확인하고 고친다. 테스트 기대값을 바꿔 통과시키지 않는다.
- 명도 대비는 수치로 계산해 보고한다.
- 실행하지 못한 항목은 "미검증"으로 적는다.

## 5. 최종 응답

다음만 간결하게 담는다.

1. 대상 프로젝트, 생성·수정한 파일 경로
2. 핵심 디자인 결정 3줄 이내 (레이아웃, 색 체계, 주요 상태 표현)
3. 검증 결과 (실행, 테스트, 대비, 미검증 항목)
4. 기능에 영향이 있어 적용하지 않은 제안 (있다면)
5. 다음 단계 제안 (예: "모바일 화면 설계 추가", "구현 코드가 생기면 이 문서 기준으로 다시 적용")

## 금지 사항
- 기능 로직, 데이터 처리, API, 저장 형식을 "디자인 작업"이라는 이유로 바꾸지 않는다.
- 사용자가 요청하지 않은 화면이나 기능을 새로 만들지 않는다.
- 프로젝트 폴더, 설정 파일, 의존성 파일을 새로 만들지 않는다.
- 검증 없이 "완성"이라고 보고하지 않는다.
- 비밀 값이나 개인 정보를 디자인 파일에 넣지 않는다.
