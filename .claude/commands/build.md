사용자 입력: $ARGUMENTS

위 기능 설명을 **실제로 동작하는 코드**로 구현한다. 이 명령은 메인 세션에서 실행되며, 구현은 `implementer` 서브 에이전트에게 맡긴다. 너는 대상 확인, 서브 에이전트 호출, 결과 검수, 테스트 확인을 맡는다.

모든 응답과 기록은 한국어로 작성한다.

## 0. 입력 확인

- 입력이 비어 있으면 시작하지 말고 "구현할 기능을 한두 문장으로 알려 주세요. 예: /build 할 일 추가, 목록 조회, 완료 표시 기능"이라고 안내하고 멈춘다.
- 대상 프로젝트를 정한다.
  - 입력에 프로젝트 이름이 있으면 그것을 쓴다.
  - 없으면 `myAgent/docs/`와 `myAgent/`를 `Glob`으로 확인한다. 프로젝트가 하나면 그것을 쓰고, 여러 개면 어느 프로젝트인지 묻고 멈춘다.
  - 프로젝트가 하나도 없으면 "먼저 /dev 또는 /plan으로 기획을 만들어 주세요"라고 안내하고 멈춘다. 구현 기준이 없는 상태에서 코드를 만들지 않는다.

## 1. 기능과 기획 대조

- `myAgent/docs/<프로젝트명>/requirements.md`, `design.md`, `structure.md`, `plan.md`를 읽는다.
- 입력한 기능이 기존 요구사항(FR-xx)에 있는지 찾는다.
  - **있으면:** 해당 FR과 연결된 작업(T-xx)을 `plan.md`에서 찾는다. 선행 작업이 끝났는지 확인한다.
  - **없으면:** 요구사항에 새 항목을 추가해야 한다. 이 명령은 새 기능 설계까지 하지 않는다. `requirements-planner` 에이전트를 호출해 해당 기능만 `requirements.md`와 `plan.md`에 추가하게 한 뒤 진행한다.
- 선행 작업이 끝나지 않았으면 그 작업부터 같이 구현할지 사용자에게 확인한다. 기본값은 선행 작업까지 포함해 구현하는 것이다.

## 2. 구현 호출 (implementer)

`Agent` 도구로 `implementer` 서브 에이전트를 호출한다. 서브 에이전트는 이 대화를 볼 수 없으므로 프롬프트에 다음을 모두 넣는다.

- 프로젝트 이름, 기획 문서 경로 (`myAgent/docs/<프로젝트명>/`)
- 코드 루트 경로 (`myAgent/<프로젝트명>/`, 단 `structure.md`에 다른 경로가 있으면 그것)
- 구현 대상: 기능 설명 원문과 연결된 FR-xx, T-xx 목록
- 완료 기준: 해당 FR의 수용 기준 전부
- 제약: 대상 기능 외의 기능 변경 금지, 기존 테스트 기대값 임의 변경 금지, 사용자 데이터 파일 보호
- 보고 형식: 변경 파일 목록, 수용 기준별 테스트 결과(실제 실행한 명령과 출력), 설계와 다르게 한 결정, 미검증 항목

## 3. 결과 검수 (직접)

- 보고된 파일이 실제로 존재하는지 `Glob`/`Read`로 확인한다.
- 테스트 명령을 `PowerShell`로 직접 실행한다. 명령은 설계 문서나 README의 실행 방법을 따른다. 없으면 implementer에게 README 작성을 요청한다.
- 수용 기준 목록과 테스트 결과를 대조한다. 테스트로 덮이지 않은 기준이 있으면 보완을 요청한다.
- 기존 기능 회귀가 없는지 전체 테스트 결과로 확인한다.

## 4. 재시도

- 검수에서 실패하면 실패 로그와 함께 같은 `implementer`에게 수정을 요청한다.
- 재시도는 **최대 2회**다. 그래도 실패하면 멈추고 실패 원인, 시도한 내용, 남은 문제를 사용자에게 보고한다. 테스트 기대값을 바꿔서 통과시키지 않는다.

## 5. 기록

- `myAgent/docs/<프로젝트명>/plan.md`에서 구현한 작업의 상태를 갱신한다. 테스트까지 통과한 것만 `완료`로 표시하고, 나머지는 `검증 대기`로 둔다.
- `progress.md`가 있으면 이번 구현 기록(날짜, 기능 설명, 결과, 재시도 횟수)을 한 항목 추가한다. 없으면 새로 만든다.

## 6. 최종 응답

1. 구현한 기능과 연결된 FR-xx, T-xx
2. 변경·생성한 파일 목록
3. 실행한 테스트 명령과 결과 (통과 수, 실패 수)
4. 설계와 다르게 한 결정이나 자동 채택한 가정
5. 미검증 또는 남은 문제
6. 실행 방법 한 줄 (예: `cd myAgent/<프로젝트명>` 후 실행 명령)

## 금지 사항
- 기획 문서 없이 코드를 만들지 않는다.
- 요청한 기능과 무관한 파일이나 다른 프로젝트(`mySchedule`, `myExpense`, `myShopping`)를 수정하지 않는다.
- 테스트를 실행하지 않고 "구현 완료"라고 보고하지 않는다.
- 실패한 테스트의 기대값을 바꾸거나 건너뛰지 않는다.
- 비밀 값이나 개인 정보를 코드나 문서에 넣지 않는다.
- 사용자가 요청하지 않은 기능을 덧붙이지 않는다.
